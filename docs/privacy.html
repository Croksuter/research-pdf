Privacy Policy

Effective October 7, 2026

Summary

  • ResearchPDF has no account and no server. The developer cannot collect or see any of your data.
  • PDF files are read only inside your browser. Their contents are not sent anywhere.
  • Web PDFs you have opened (and local PDFs that carry an arXiv stamp) are kept in the extension's storage on this device so they reopen quickly (up to 1 GB; you can turn this off or clear it in settings). These copies never leave the device.
  • Only if you connect a Google account are your drawings, reading positions and the list of PDFs you opened (titles and addresses, pinned or not) saved in an app-only folder in your own Google Drive.
  • With paper info on, only paper identifiers (DOI, arXiv ID, title) are looked up in scholarly databases.

Data stored in your browser

The following stays in the extension's local storage (IndexedDB, chrome.storage) and is deleted with the extension.

  • Document identifiers (the PDF's internal ID and a hash of the file), the last page and zoom, the file name or URL
  • The documents opened in a PDF tab: address, file name, PDF title and recognised paper title, when last opened, pinned or not
  • Your annotations (pen, highlight, text, stamp)
  • Projects: name, documents, pinned documents, the tabs open when closed, icon and color, folders and order
  • A cache of paper lookups
  • Settings, and the Semantic Scholar and OpenAlex API keys if you entered any

Google Drive sync (optional)

When you connect a Google account in settings, ResearchPDF asks only for the Google Drive API's drive.appdata scope. It reaches only a hidden app-only folder; ResearchPDF cannot even list your other Drive files.

  • What is synced: document identifiers, reading page and zoom, file name or URL, your annotations, the list of PDFs you opened (address, title, when last opened, pinned or not, kind of paper), projects (name, documents, pins, the addresses of the tabs that were open, icon and color, folders and order). One gzip-compressed JSON file.
  • What is not synced: the PDF files themselves, the paper-lookup cache, settings, API keys.
  • The data is stored only in your Google account. There is no developer server, and the developer has no access to it.
  • Sign-in happens on Google's OAuth screen. ResearchPDF never handles your password, stores no long-lived (refresh) token, and keeps only an access token of about an hour in the browser session's memory.
  • "Disconnect" revokes the token and removes the account details from this device. You can delete the data in Drive yourself under Google Drive settings → Manage apps.

ResearchPDF's use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Paper info (optional, on by default)

When the viewer recognises a DOI, arXiv ID or title in an open PDF, it looks up only that identifier in Semantic Scholar, OpenAlex, Crossref and arXiv. If the databases have no reference list, the reference list printed in the PDF is read on the device, and only each entry's DOI, arXiv ID or title is looked up in OpenAlex to add citation counts. Documents opened with an earlier version are checked once the same way while the PDF tab is idle, reading only the copy stored on the device and never downloading the PDF again. No other PDF text is sent. Figure and table detection, and reading a formula as LaTeX, run on the device with models shipped inside the extension; page images are not sent anywhere. If you enter an API key, it is sent to that service with the requests. You can turn paper info off in settings.

Permissions

  • storage, alarms: storing the data above locally, and syncing periodically.
  • webNavigation: noticing when a tab goes to a PDF address or a local PDF file, to open it in the PDF tab. Page contents are not read.
  • declarativeNetRequestWithHostAccess: only when "Open web PDFs in ResearchPDF" is on and site access is granted, six rules send responses that are PDFs to the built-in viewer — top-level documents to the PDF tab, PDFs embedded in a page (iframe, embed/object) to the viewer in their place — each for a PDF content type, an application/octet-stream response whose address ends in .pdf, or an inline .pdf file name. Downloads (attachments) and POST responses are left alone.
  • identity: opening Google's sign-in window.
  • Site access (optional): requested only when you turn on "Open web PDFs in ResearchPDF" (or allow it from the viewer). Used to send PDF responses to the viewer as above; for the viewer to download the PDF, show it and keep its copy on this device; and to read the addresses and titles of tabs showing a PDF in Chrome's own viewer, so that home, settings and the welcome guide can offer to gather them into the PDF tab. Those addresses and titles stay on the device.
  • File URL access (you turn it on in Chrome): reading PDF files on your computer in the viewer, and finding local PDFs open in Chrome's viewer to offer gathering them.

What is not collected

There are no analytics, ads, tracking or remote logging. The developer receives no data at all, usage statistics included.

Changes and contact

If this policy changes, the effective date on this page is updated. Contact: croksuter@gmail.com

개인정보처리방침

시행일: 2026년 10월 7일

요약

  • ResearchPDF에는 계정도 서버도 없습니다. 개발자는 사용자의 어떤 데이터도 수집하거나 볼 수 없습니다.
  • PDF 파일은 브라우저 안에서만 읽습니다. 파일 내용을 어디에도 전송하지 않습니다.
  • 한 번 연 웹 PDF(와 arXiv 표시가 있는 로컬 PDF)는 빠르게 다시 열 수 있도록 이 기기의 확장 저장소에 보관합니다(최대 1GB, 설정에서 끄거나 비울 수 있음). 이 사본은 기기 밖으로 나가지 않습니다.
  • Google 계정을 연결한 경우에만, 그림과 읽던 위치, 열어 본 PDF 목록(제목과 주소, 고정 여부)이 사용자 본인의 Google Drive 앱 전용 폴더에 저장됩니다.
  • 논문 정보 표시를 켠 경우, 논문 식별자(DOI, arXiv ID, 제목)만 학술 데이터베이스에 조회합니다.

브라우저에 저장되는 데이터

다음 데이터는 확장 프로그램의 로컬 저장소(IndexedDB, chrome.storage)에만 보관되며, 확장 프로그램을 삭제하면 함께 삭제됩니다.

  • 문서 식별자(PDF 내부 ID와 파일 해시), 마지막 페이지와 확대 상태, 파일 이름 또는 URL
  • PDF 탭에서 연 문서 목록: 주소, 파일 이름, PDF 제목과 인식된 논문 제목, 마지막으로 연 시각, 고정 여부
  • 사용자가 그린 주석(펜, 하이라이트, 텍스트, 스탬프)
  • 프로젝트: 이름, 속한 문서, 고정한 문서, 닫을 때 열려 있던 탭, 아이콘·색, 폴더와 목록 순서
  • 논문 정보 조회 결과 캐시
  • 설정값과 선택적으로 입력한 Semantic Scholar·OpenAlex API 키

Google Drive 동기화 (선택)

설정에서 Google 계정을 연결하면 ResearchPDF는 Google Drive API의 drive.appdata 권한만 요청합니다. 이 권한은 앱 전용 숨김 폴더에만 접근할 수 있으며, 사용자의 다른 Drive 파일은 목록조차 볼 수 없습니다.

  • 동기화되는 것: 문서 식별자, 읽던 페이지와 확대 상태, 파일 이름 또는 URL, 그린 주석, 열어 본 PDF 목록(주소, 제목, 마지막으로 연 시각, 고정 여부, 논문 종류), 프로젝트(이름, 속한 문서, 고정, 열려 있던 탭의 주소, 아이콘·색, 폴더와 순서). gzip으로 압축된 JSON 파일 하나입니다.
  • 동기화되지 않는 것: PDF 파일 자체, 논문 정보 캐시, 설정, API 키.
  • 데이터는 사용자의 Google 계정에만 저장됩니다. 개발자가 운영하는 서버는 없으며 개발자는 이 데이터에 접근할 수 없습니다.
  • 로그인은 Google의 OAuth 화면에서 이루어집니다. ResearchPDF는 비밀번호를 다루지 않고, 장기 토큰(refresh token)을 저장하지 않으며, 약 1시간짜리 액세스 토큰만 브라우저 세션 메모리에 보관합니다.
  • "연결 해제"를 누르면 토큰을 폐기하고 이 기기의 계정 정보를 지웁니다. Drive의 데이터는 Google Drive 설정 → 앱 관리에서 사용자가 직접 삭제할 수 있습니다.

ResearchPDF가 Google API에서 받은 정보를 사용하고 다른 앱으로 전송하는 것은 Google API 서비스 사용자 데이터 정책(제한적 사용 요구사항 포함)을 따릅니다.

논문 정보 표시 (선택, 기본 켜짐)

뷰어가 열린 PDF에서 DOI, arXiv ID 또는 제목을 인식하면 그 식별자만 Semantic Scholar, OpenAlex, Crossref, arXiv에 조회합니다. 데이터베이스에 참고문헌 목록이 없으면 PDF에 인쇄된 참고문헌 목록을 기기 안에서 읽고, 각 항목의 DOI·arXiv ID·제목만 OpenAlex에 조회해 인용 수를 붙입니다. 이전 버전에서 열어 둔 문서는 허브가 한가할 때 같은 방식으로 한 번씩 다시 확인합니다. 이때 PDF는 기기에 저장된 사본만 읽고 웹에서 다시 받지 않습니다. 그 밖의 PDF 본문은 전송하지 않습니다. 그림·표 자동 인식은 확장 프로그램에 들어 있는 모델로 기기 안에서만 실행되며, 페이지 이미지를 어디에도 보내지 않습니다. API 키를 넣으면 해당 서비스에 그 키를 함께 보냅니다. 설정에서 끌 수 있습니다.

권한

  • storage, alarms: 위 데이터의 로컬 저장과 주기적 동기화.
  • webNavigation: 탭이 PDF 주소나 로컬 PDF 파일로 이동하는 순간을 알아 PDF 탭으로 엽니다. 페이지 내용은 읽지 않습니다.
  • declarativeNetRequestWithHostAccess: "웹 PDF도 ResearchPDF로 열기"를 켜고 사이트 접근을 허용한 경우에만, PDF인 응답을 내장 뷰어로 돌리는 규칙 6개를 둡니다. 최상위 문서는 PDF 탭으로, 페이지에 끼워 넣은 PDF(iframe, embed/object)는 그 자리의 뷰어로 보내며, 각각 Content-Type이 PDF인 응답, 주소가 .pdf로 끝나는 application/octet-stream 응답, inline으로 .pdf 파일 이름을 단 응답에 적용됩니다. 다운로드(attachment)와 POST 응답은 건드리지 않습니다.
  • identity: Google 로그인 창을 열기 위해 사용합니다.
  • 사이트 접근 권한(선택): "웹 PDF도 ResearchPDF로 열기"를 켤 때(또는 뷰어에서 허용할 때)만 요청합니다. 위처럼 PDF 응답을 뷰어로 돌리고, 뷰어가 PDF 파일을 내려받아 표시하고 이 기기에 보관하며, Chrome 기본 뷰어로 PDF를 보여 주는 탭의 주소와 제목을 읽어 홈·설정·시작 가이드에서 PDF 탭으로 모으자고 제안하는 데 씁니다. 이 주소와 제목은 기기 밖으로 나가지 않습니다.
  • 파일 URL 접근(사용자가 Chrome에서 켬): 컴퓨터의 PDF 파일을 뷰어로 읽고, Chrome 기본 뷰어에 열린 로컬 PDF를 찾아 모으자고 제안하는 데 씁니다.

수집하지 않는 것

분석 도구, 광고, 추적, 원격 로깅이 없습니다. 개발자는 사용 통계를 포함해 어떤 데이터도 받지 않습니다.
